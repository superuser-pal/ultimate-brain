# Selected input: what enters the brain (decision 0055)

Read this when the summary of a meeting or a capture has subjects and item ids (`[s1] …`, `[s1.i1] … "quote"`; notion/minutes-format.md, notion/voice-format.md). The user decides what enters the brain by marking subjects or items `Meeting only`; the brain stores **only the selected paragraphs of the transcript** as an extract and builds every note from that. Contract: spec/capture-and-review.md §3, §4, §6; commands: spec/cli.md §5.22, §5.23.

**Which flow?** The summary's shape decides it (spec/capture-and-review.md §4.1, "Shapes"); `extract-plan` reads the same rule:
- **Lean** (decision 0079, the minutes prompt from 0.14.0): the summary holds a toggle **For the brain**. The readable part above it is for the user (In one line, Quick follow-ups with `[q1]` tags, Tasks for the brain, one block per subject with `Decided:`, `Open:` … lines); the toggle holds the Attendees and Projects lines, each subject's `Selection:` line and the quotes of each item, by id. Read by this file, with "The lean shape" below. A page with a For the brain toggle is always lean, even with its ids lost: never store it whole.
- **Inline-quote:** subject and item ids (`[s1]`, `[s1.i1] … "quote"`) and no For the brain toggle: the 0055 and 0067 minutes and the voice format. Read by this file exactly as before 0.14.0: no rule of "The lean shape" applies, and a `[q1]` is plain text.
- **Legacy:** **no** `[s…]` id anywhere and no For the brain toggle (a meeting summarised before this format, or by another tool): ingest it whole by the procedure in SKILL.md, unchanged, and add to **Check**: "<title>: no subjects or ids, so nothing could be left out".

Never ingest the whole transcript because a selection failed.

**The lean shape, in short** (the contract is spec/capture-and-review.md §3.3 and §4.1). Each item's text is written once, on its readable line, ending (or starting) with its id tag; the toggle joins it to its quotes by the id. A line the user corrected in the readable part is the text you read. `Meeting only` and `Use in brain` are marked only in the toggle, on a subject's `[s2] Selection:` line or at the start of an item's quote entry; `Track: Waiting On —` stays on the readable line, before its text. A `Waiting on <name>:` prefix alone only says what kind of line it is: it never makes a Waiting On Task. The toggle's `Attendees:` and `Projects:` lines are the minutes' Attendees and Projects (SKILL.md step 3: they fill an empty Meeting property, as a `## Projects` section does). The In one line line is never an item and never imported.

## 1. Confirmed? (both modes)

- The input counts only when its status is **Reviewed** (Meetings) or **Ready** (Inbox). Reviewed/Ready confirms the selections the page shows when the first run that sees it reads them, and nothing else. A New or Not Reviewed input is unconfirmed: never read, never ingested, and **never set to Reviewed/Ready by you** (an unattended run in particular).
- An **unattended** run takes a confirmed input only when the page's `last_edited_time` is at least **2 minutes** older than the run; otherwise it waits (`TOO_FRESH`) and is named under Needs you. Its report says that an edit made in the confirming minute cannot be detected.

## 2. Read and plan

1. Read the summary and the transcript of the page through the Notion MCP (the meeting's transcript tool for a meeting; the **Transcript** toggle for a capture). Write them verbatim to two temporary files outside the brain. For a Notion AI meeting-notes block the summary is what its own `<summary>` holds: drop that block's wrapper tags (`<meeting-notes>`, its `<summary>` and `</summary>`) and nothing else. Every toggle inside the summary stays whole, as the page's Markdown gives it: the For the brain toggle of lean minutes (`<details>`, `<summary>For the brain</summary>`, its lines with their indentation, `</details>`) and a Scope toggle. So do the to-do boxes as they are now (`- [ ]`, `- [x]`). `extract-plan` reads the selection from the toggle and the ticks from the boxes; with the toggle's tags removed its lines block as `SELECTION_UNREADABLE`. Rule 3 of [notion.md](notion.md)'s source body (dropping `<details>` and its indentation) is for a summary stored whole and never applies here.
2. Is this the first read? Look for sources of the page: `grep -l "notion:<page id>\|extract_of: <page id>" sources/*/*.md` (frontmatter `source_key`, `extract_of`; an administrative lookup that gives paths and ids, never content). If there are any, pass `--previous <the latest one>`: the source that no other source names in `replaces` (for an input ingested in full before selection, its latest non-extract source). Without it a second read stops with `PREVIOUS_REQUIRED`; a wrong pick stops with `NOT_LATEST`.
3. Run `brain source extract-plan --page <page id> --summary <file> --transcript <file> [--previous <src>]`. Read `data`:
   - `ok: false` → **blocker** (below). Nothing may be written.
   - `copied`: the full text of every paragraph that would enter, with the items citing it. `uncovered`: the number of paragraphs no item cites (they do not enter). `unnumbered`: list lines with no id (a blocker). `problems`: `DEPENDS_ON_EXCLUDED` items are listed, not blocking.
   - Never blocking (decision 0067): `quotes`, an included item's quotes placed by a shorter stretch (`shortened`) or not placed (`unplaced`); `unplaced_items`, included items with no placed quote, which are **not imported** (nothing from them, no Task); `quick`, the Quick follow-ups lines, which never become a note, a fact or a report line (in the lean shape an unticked follow-up becomes a Task, §6); `scopes`, each task's Scope toggle (§6).
   - **Lean shape only** (`shape: "lean"`; absent for the other shapes):
     - `items`, one per readable item line, in page order: `id`, `subject` (null for `s0`), `place` (`tasks`: the Tasks for the brain group; `subject`: its subject's block), `prefix` (`decided`, `open`, `concern`, `waiting_on`, `idea` or null), `name` (of a `Waiting on <name>:` prefix), `track` (the line carries `Track: Waiting On —`), `text` (the line as the user sees it, prefix kept) and `anchors` (its quotes). `text` is the item's wording: what it says, not its prefix or its place, decides what it is (§6);
     - in each `quick` entry, `follow_up` (its `q` id, or null), `task` (true: it becomes a Task at this read, §6) and `recorded` (the page id of the Task it already has, or null);
     - three problems that never block: `NO_QUOTE_ENTRY` (a readable line with no quote entry: when included it is in `unplaced_items` and not imported; when excluded it is also `SELECTION_UNMAPPABLE`, a blocker), `ORPHAN_QUOTE_ENTRY` (a quote entry with no readable line: nothing is imported from it), `DUPLICATE_FOLLOW_UP` (one `q` id on two to-dos: neither becomes a Task).
   - `write_required` (top level; `false` means `UNCHANGED`: no new version; go on to Tasks, §6);
   - with `--previous`, under `data.previous`: `transcript_changed`, `suppressed`, `added`, `selection_changes`, `legacy_tasks`, `full_copies`.

## 3. Blockers

`SELECTION_UNREADABLE` (a token spelled wrongly, a control in the wrong place), `SELECTION_UNMAPPABLE` (an **excluded** item's quote found in no paragraph or in several, or missing; a missing `depends on` id or a cycle; or "shares a paragraph with excluded content"), `UNNUMBERED_LINE` (a list line with no id outside Quick follow-ups). In the lean shape `SELECTION_UNREADABLE` also covers a selection token on a readable line, a `Selection:` line outside the For the brain toggle, a second For the brain toggle or a toggle inside it, and a line with two id tags or one in the middle of its text; `UNNUMBERED_LINE`, a line of a subject block or of Tasks for the brain whose id tag was lost. The input is a blocker, not a partial ingest. An included item's quote problem is not a blocker (decision 0067): it is in `quotes` and `unplaced_items`.
- **Attended:** show each problem with its line, and offer the **repair** for unmappable items: propose longer quotes (copied from the transcript, at most twelve words, unique) or tighter ones that cite a different paragraph, for the user to confirm in the preview. Offer the same repair, in the preview, for `unplaced_items` and `unplaced` quotes; the user may go on without it. For an unnumbered line propose an id and quotes. In the lean shape a repaired quote goes in the item's quote entry inside the toggle, and a token found on a readable line moves to the start of that item's quote entry (or to its subject's Selection line). Apply confirmed repairs to your temporary summary file only (never edit the Notion page's tokens or text), then run `extract-plan` again, and tell the user to fix the same lines on the Notion page (ask Brain Assistant to "check minutes"): the page keeps the old text, so the next read blocks again until they do. For a collision between an excluded and an included item, say which two items collide; if the shared words cannot be separated, the input stays blocked.
- **Unattended:** skip the input and name it and the line under Needs you.

## 4. Preview, then write (attended)

Show, before anything is written: every subject and item with its **effective selection** (the item's own token, else its subject's, else use), the **full text of each paragraph that will be copied** with the items citing it, the paragraphs covered by no item ("n paragraphs are covered by no item"), the unnumbered lines, the items listed "depends on excluded context", the `shortened` quotes with the stretch used, the `unplaced_items` ("not imported: fix the quote on the page"), the number of quick follow-ups left in Notion, and, with `--previous`, what changes (`suppressed`, `added`, `selection_changes`, `transcript_changed`). A transcript change suppresses every paragraph of the old version: say so. In the lean shape, with the Tasks module on, also the follow-ups that become Tasks, with their text ("2 quick follow-ups become Tasks: Send Ben the supplier's phone number; Ask Carla for the shed key. To keep one out, tick or delete it on the page"), and the ones held back (§6, "Follow-ups"). Import only after a yes.

**Read the page again after the yes** when it holds follow-ups that become Tasks, before writing anything: the page as read then is what counts (spec/capture-and-review.md §4.4, §6.3). When the summary is unchanged, write. When it changed (a follow-up ticked or deleted to keep it out, a token, a line), run §2 step 3 again on the new text and preview again.

Then run `brain source extract --page <id> --title "<title>" --date <YYYY-MM-DD> [--kind capture] --summary <file> --transcript <file> [--previous <src>]`. It writes the extract, its suppression record and the regenerated views as one journaled, committed operation. `UNCHANGED` means nothing to write. On `RECOVERY_NEEDED`, run `brain recover` and stop if it fails.

**Unattended:** a first version of a confirmed, settled input is written without a preview. A re-read that changes the transcript is skipped (it suppresses everything) and named under Needs you; a re-read with the same transcript is written only when the page is settled, and the report names the suppressed and added paragraphs.

## 5. Ingest from the extract

The extract is the source; do **not** `note new` a source (that stops at `DUPLICATE_SOURCE`). Run steps 4–11 of SKILL.md with the extract's id as `source` and read **only the extract's paragraphs** (the transcript and the rest of the summary stay in Notion). You saw the excluded items and their paragraphs while planning: nothing of them is written, cited or not (SKILL.md, "The writing rule"). In the lean shape an item's wording is its `items` `text`, the line the user may have corrected: it decides what the notes say, and the paragraphs its quotes place are the evidence each claim cites. The readable text is never stored as such: the extract holds the paragraphs only. Every claim you write cites its paragraph, and every proposal names the paragraphs it draws from in `passages` ([cli-inputs.md](cli-inputs.md) §3):
- in a note body, a marker `^[src-…#¶n:<passage_hash>]` after the statement; in a timeline entry, the field `passage` (`src-…#¶n:<hash>`); the hash is in the extract's `passages`. `brain lint` requires it;
- an item with `context_excluded` (explicit `use` whose context was excluded) makes each claim from it carry `context_excluded: true`, and Review shows it;
- an excluded item, or an item "depends on excluded context" without its own `Use in brain:`, creates **nothing** anywhere: not a note, a fact, a Task, a link or a report line.

A re-read runs the ordinary comparison on the extract's paragraphs (SKILL.md, "A re-read"): corrected wording supersedes the old statement, and only changes without a pending or decided proposal for the same target become Review items, so a second run finds nothing new.

**No durable knowledge is a valid result:** write the extract, propose nothing, say so.

## 6. Tasks

With the Tasks module off or no Tasks database configured (`brain status`), write no Task items and say nothing about them; the summary and the notes are written as usual.

Only the owner's **explicit** commitments become Tasks. The owner comes from the configured identities and aliases (`brain.json` `owner`), never from a name in a prompt. Take them from numbered items that are effectively selected, of a confirmed input.
- **Whatever the section** (decision 0071, [extraction.md](extraction.md) "Questions or commitments"): an item under Open questions or Highlights that is the owner's explicit to-do is a Task like an item under Tasks (it carries its `item` id; with no Scope, the fields fall back to the rules below); someone else's is text. **Neither is ever a question note.** Only what a later document or meeting can settle is a question, and a concern is a risk.
- **With Tasks off**, the owner's to-dos stay in the meeting's `## Action items`, like other people's commitments, and are still not questions.
- An ambiguous owner, "needs clarification", or a tentative idea ("we could…") → **no Task**. Say so under Check.
- Another person's commitment → **no Task**, unless the item carries `Track: Waiting On —`. Then `brain sync tasks --source <extract> --input` takes `{ "title", "status": "waiting_on", "owner": "<their name>", "item": "s1.i3" }`; the summary's `Track` token is the user's explicit request, you never add it. If `brain.json` `notion.tasks.properties.owner` is empty the person's name cannot be stored: tell the user, and start the title with "Waiting on <name>: " yourself. Offer it once in the preview ("Maria said she will send the plan: track it? write `Track: Waiting On —` before that item") but create nothing until the token is on the page.
- **Selected inputs use `brain sync tasks --source <the extract's src id>`, for owner Tasks too** (`--meeting` refuses an `item`). Each item is `{ "title", "item": "s1.i3", "projects": [the meeting's or the row's project ids], "due"? }`: `--source` does not copy the meeting's projects, so pass them yourself; it sets no Meeting relation (the Task links to the extract's Inbox row). Every owner Task carries `"item": "<item id>"`. Record the Task with `brain sync record` including `task_items` (`{ "<item id>": "<Notion task page id>" }`).
- **Quick follow-ups** (`quick`) never become Tasks, whatever they say, except an unticked follow-up of the lean shape ("Follow-ups", below). In the inline-quote shape no follow-up ever becomes a Task, at a first read or a re-read.
- **In the lean shape** the items that can become Tasks are the readable item lines (`items`): those under Tasks for the brain and those in a subject block, by the rules above. A Tasks for the brain line takes its subject from its id, not its place: a subject marked `Meeting only` excludes it too.
- **Scope (decision 0067).** For an item that becomes a Task, look up its entry in `scopes` (`item` = the item id). `due` → the item's `due` (it replaces a date read from the text); `project` → resolve the name to a project note by title or alias (`brain query --candidates "<name>" --types project`), and pass that id alone in `projects` (it replaces the project you would infer); `done_when` and `notes` → the page body, written when you create the Task page: a paragraph `Done when: <text>`, then a heading `Notes` and the notes (`sync tasks` has no body field). An absent field falls back to the rules above. **A Scope you can't use holds back only that Task:** a Scope with `problems`, or a `project` that names no project or several. Attended: say why and ask (fix it on the page and run again, or create the Task without that field). Unattended: create no Task for that item and name it under Needs you. A Scope with `item: null` belongs to no item: name it under Check. A Task already created for the item (below) is never updated from its Scope.
- **Never twice:** an item with an entry in `task_items` anywhere along the `replaces` chain gets no second Task (`task_items` and `replaces` are ids in the sources' frontmatter: reading them is an administrative lookup, like step 2's). An item the brain already holds as a question (a question note raised in this meeting that says what the item says, open, answered or dropped; found with `brain query --candidates --types question` and read with `brain query --read`) gets **no Task** on a re-ingest, even if it now reads as your to-do: only the to-do tidy converts it ([todo-tidy.md](todo-tidy.md)); an item whose wording the user changed into a to-do gets its Task once, unless that question was dropped with a `task`, and the old question is named under Check. While `legacy_tasks` is not empty create **none** automatically: list the item as "possible Task" with the existing Tasks' links; an attended run creates it only after the user confirms, an unattended run skips it and names it under Needs you. Never cancel or delete a Task.

**Follow-ups (lean shape only, decision 0079; spec/capture-and-review.md §6.3).** A quick follow-up the user left unticked when they marked the page Reviewed becomes a Task, once.
- **Which:** each `quick` entry with `task: true`: an unticked to-do with a `q` id and some text, its id on no other to-do, and no Task recorded for that id along the `replaces` chain. Nothing is classified: the boxes are the owner's own list, so an unticked follow-up becomes a Task whatever it says (the to-do and question rules above don't apply), and neither `Meeting only`, `legacy_tasks` nor a Scope holds it back.
- **When:** only at a read that ingests the input (its first read, or a read the user asked for by setting it back to Reviewed or Ready), after the version decision, also when the version is `UNCHANGED`. An input that is unconfirmed, blocked, `TOO_FRESH` or skipped creates none: its follow-ups are read, ticked or not, at the read that ingests it. Never look at an ingested page again for follow-ups: one left unticked after the read waits for the next read the user asks for.
- **The Task**, in the publish's Tasks step with the input's other Tasks: `brain sync tasks --source <the latest extract of the input> --input` with `{ "title": "<its quick text>", "follow_up": "<q id>", "projects": [<the meeting note's projects after this ingest; for a capture, its row's Project>] }`. Nothing else: no `item`, no `due` even when the text names a date, no `owner`, `status`, Scope, page body or marker. `sync tasks` refuses a `q` id that already has its Task (`INPUT_INVALID`, naming the page): create nothing for it and name it under Check.
- **Record it** with `brain sync record`: on the extract `{ "id": "<src id>", "synced_at": "<now>", "tasks": ["<page id>"], "task_items": { "<q id>": "<page id>" } }`, and on the meeting `{ "id": "<mtg id>", "synced_at": "<now>", "tasks": ["<page id>"] }`. The `q` id is the follow-up's only identity: a later read never creates its Task again, whatever its text now says, and a Task is never matched by its title. A run that stops between creating a Task and recording it can create it again on a retry.
- **Nothing in Git but the id:** a follow-up has no quote, so its text never goes in a note, the meeting, a proposal, the log or a commit message. Its only trace is the `q` key in `task_items` and the page id. Reports give a count; the text goes only in the preview and the Check lines.
- **The checkbox is the user's:** never tick, edit or annotate it (decision 0007). A user who wants one kept out ticks or deletes it before marking Reviewed; there is no token for it.
- **Tasks module off,** or no Tasks database: follow-ups stay in Notion and you say nothing about them. A later read with the module on creates them by these rules.
- **Unattended:** created the same way, with no question.
- **Held back, never silently.** Name under Check, attended and unattended, each unticked follow-up that creates no Task: one that already has its Task (`recorded`: "Garden call: q1 is already a Task"), one whose `q` id is on two to-dos (`DUPLICATE_FOLLOW_UP`: name both, "renumber one and set the meeting back to Reviewed"), one with no text, and a to-do with no `q` id in a lean Quick follow-ups group ("stays in Notion").
- **A regenerated summary** may number its follow-ups again: a follow-up whose new `q` id already has a Task gets none, and one that got a Task under another id may get a second. This is a stated limit: the `q` id is the only identity.

## 7. Changes after ingestion

The brain does not watch ingested pages: deleting a line in Notion is not a request. The user asks by setting the meeting back to **Reviewed** (the Inbox row to **Ready**) after editing the tokens, or by telling you. Then follow sections 2–4 with `--previous`, and run the ordinary ingest comparison (SKILL.md, "A re-read"). Setting the status again is also how the user asks the brain to check the input against what it already knows.

When an extract version suppresses or re-includes paragraphs, claims resting on them are restricted at once. After the version is written and committed, run `brain source cleanup-propose --page <id>`: it writes one **Exclusion cleanup** Review row (Remove, Restore, Keep/Remove items). Unattended, this is only an addition; nothing is removed. Tasks created from excluded content are listed in the row; you never cancel them.

## Report

On the Done line, the follow-ups that became Tasks are counted inside the Tasks count: "4 tasks created (2 from quick follow-ups)"; leave the bracket out when there are none.

Under Check: unconfirmed inputs left waiting, blockers with their lines, paragraphs covered by no item, items "depends on excluded context", `unplaced_items` (not imported until their quote is fixed on the page) and how many quotes were `shortened`, readable lines with no quote entry and quote entries with no readable line (`NO_QUOTE_ENTRY`, `ORPHAN_QUOTE_ENTRY`), Tasks held back by their Scope, follow-ups held back (§6, "Follow-ups"), legacy summaries that could not be narrowed, the confirming-minute limit (unattended), and Tasks listed as "possible".
