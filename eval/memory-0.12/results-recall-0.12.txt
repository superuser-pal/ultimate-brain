Failures and their causes
-------------------------

1. trust-10, trust-11, trust-12 (trust/exclusion), unk-08 (unknown): `brain query --candidates` returns
   dec:velmor-discount (dec-cdfq7bz5). Its one body line cites the excluded passage (src-14dbsdjq ¶2), so
   the line is blanked and the summary dropped, but cli.md §5.13 leaves a note out whole only for an
   unmapped line or an unsupported fact: the note still comes back, by its title, with every claim blanked.
   Fix: CC-174 (a knowledge note with every claim restricted and nothing else left is left out whole).

2. trust-15 (trust/supersession): for "Should I set up the new Harbor environment on Fly.io?" from
   harbor-web, `brain query --candidates` ranks the superseded, archived dec:harbor-flyio (dec-v15x3kfr,
   score 32) above the live dec:harbor-hetzner (dec-t61ttsk1, score 20). §5.13 has no live-before-superseded
   rule for knowledge notes; 0009's ranking covers memories only. Fix: CC-173 (live before superseded for
   knowledge notes).

3. ans-32 (answerable/current; mem:q-ses, mem-sa3ybr46), ans-26 (answerable/paraphrase) and ans-34
   (answerable/correction; both prj:orbit, prj-b0414hmr): left out whole by the restricted-evidence rule
   (src/lib/suppressions.ts, restrictionOf). A provenance entry that is not a source note (the memory's
   `sources: [dec-n4pxymgr]`; the project's timeline `source: notion-edit`, which schema.md allows) gets no
   lineage, so it is treated as unknown lineage and restricted while any suppression is active, here the
   Harbor pricing call's, in another project. Lint's `unknown-lineage` (cli.md §5.10) doesn't flag these
   entries, so lint and retrieval disagree. Fix: CC-174 (a note id, `agent:…`, `notion-edit` or
   `user-correction:…` entry is not unknown lineage).

4. unk-04 (unknown): `brain query --candidates` returns prj:harbor (prj-4z086p0f) for "When does the Orbit
   app go live?" from orbit-app. No task: a limit of a retrieval-only adapter. Knowledge notes reach every
   caller, and unknown cases are judged on answers, which no adapter here writes.

Not exercised: no pack reached its budget (omitted is 0 everywhere), so the left-out-whole rule of
memory.md §5.1 step 3 is covered by tests/recall.test.ts, not by this set.
