# Lean minutes and follow-up Tasks: acceptance run (CC-198)

CC-198's acceptance (decision 0079 §4; spec/capture-and-review.md §4.1, §6.3; spec/cli.md §5.14.5, §5.14.6, §5.22). [run.mjs](run.mjs) follows brain-ingest's `references/selection.md` as CC-198 writes it in the skills fork (#24 and #25, released in brain-v1.8.1 and vendored here), one step at a time, with this branch's CLI on a synthetic sandbox. It writes each command and what it returned to [runs/steps.md](runs/steps.md), and checks the outcomes.

**To reproduce:** `npm run build`, then `node eval/follow-ups-0.14/run.mjs` (exit 0 when every check passes). The trace's ids differ from run to run.

**What the sandbox is.** The synthetic `brain-acme` fixture in a temporary folder, as a Git repository, with a `gh` that always fails and every command run with `--brain`. The minutes and the transcript are CC-196's synthetic fixtures (`tests/fixtures/minutes-0079/`): `lean-summary.md` (q1 and q3 unticked, q2 ticked; s2 and s4 `Meeting only`, s4.i2 `Use in brain`) and `inline-summary.md` (the 0.9.x shape, with a `[q1]` on a quick follow-up). Notion is simulated: a Task the skill would create is a made-up page id.

**Scripted, not blind.** The author of the skill change wrote the script that follows it, so this run shows that the skill's steps, done as written, reach the contract's outcome with the real CLI. It doesn't show how a model reads the text. The step that only a model does (the analysis of SKILL.md step 6) is reduced to the meeting note the Tasks are recorded on.
