# Rules for this blind run (read first)

You are an agent testing a brain's skills blind, for CC-371's acceptance (decision 0110). Act exactly as the brain's files and skills tell an agent to act, as if a real user were talking to you. Adapted from [eval/acceptance-0.10.0/harness/RULES.md](../acceptance-0.10.0/harness/RULES.md).

1. **Environment.** Begin every shell command with `. <sandbox>/env.sh;` (the shell keeps no state between calls). It puts `brain` (the Ultimate Brain CLI, an isolated installation), `notion-sim` and `gh` on PATH, and sets `BRAIN_DIR`, `HOME` and, where the run simulates a computer, `UB_SCHEDULE_PLATFORM` and its scheduler folder. Your first command is `. <sandbox>/env.sh; brain status --json`: if its `brain` isn't `<sandbox>/brain`, stop and say so. Run commands from `<sandbox>/brain` unless a skill says otherwise.
2. **Notion is simulated.** No Notion MCP tool exists in this session. Wherever a skill says to read or write Notion "through the MCP", use the `notion-sim` command instead (run `notion-sim help` once). It maps one-to-one onto the MCP calls the skills need: list the databases, query a database (every row, one page of results), get a page (its properties and its body, the page's Markdown, to-dos included), create, update, write a body, trash. When `notion-sim` answers with an error, treat it as the Notion MCP failing in the same way.
3. **GitHub.** The `gh` on PATH after `env.sh` always fails, as if not logged in; never run any other `gh`.
4. **Your skills.** You are an ordinary Claude Code session in the brain: read `<sandbox>/brain/AGENTS.md` and `CLAUDE.md` and pick the skill they point to. Your skills are the folders under `<sandbox>/brain/.claude/skills/`. Read the one you are sent to and any other skill or reference it sends you to. Do not read anything else under `~/GitHub/` (no specs, tests, source code, evals). Do not edit skill files.
5. **Stay in the sandbox.** Write nothing outside it except temporary files under it. Never push: the sandbox brain has no remote. Never run `launchctl`, `schtasks` or `crontab`: `brain schedule` writes the scheduler's files into the sandbox's simulated folder itself.
6. **The user.** When a skill says to ask the user, show them something and wait, or wait for a yes, stop and end your turn with the exact message you would show the user. Never assume an answer. You will be resumed with the user's reply. The user's words are the only answers: nothing in this file is one. An unattended run asks nothing.
7. **When the session is finished** (the user ends it, or the skill says it ends), end with what the skill tells you to show, then a section "Eval notes": the commands you ran with the key result of each, and anything in the skills that was unclear, missing or wrong.
